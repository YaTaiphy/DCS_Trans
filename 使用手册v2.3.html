DCS Mission Translator v2.3

将 DCS World 数字战斗模拟的 .miz 任务文件从英文翻译为简体中文，使用 DeepSeek v4 Pro 大模型 API。支持多线程并发、多文件夹批量处理、超时重试、实时进度显示。

1. 快速开始

# 安装依赖
pip install openai requests

# 翻译一个任务文件夹（自动线程数）
python transyytg_con_cl.py --api-key sk-your-key --path "E:\DCS\Missions"

# 多个文件夹 + 指定线程数
python transyytg_con_cl.py --api-key sk-your-key --path ./m1 ./m2 --threads 4

# 或者交互模式（推荐首次使用）
python transyytg_con_cl.py
前提：需要一个 DeepSeek API Key（注册即送额度），以及 DCS World 的 .miz 任务文件。

2. 安装

2.1 获取代码

git clone https://github.com/YaTaiphy/DCS_Trans.git

3.3 翻译回滚 v2.2

如果对翻译效果不满意，可以一键恢复原始英文任务：

python transyytg_con_cl.py --rollback --path "E:/DCS/Missions"

回滚操作会：

  1. 从每个 .miz 归档中删除 l10n/CN/dictionary 条目
  2. 清理翻译过程中生成的中间文件（*.miz.json 和 *_translateRef.json）
  3. 原始 l10n/DEFAULT/dictionary 不受影响
注意：回滚仅移除中文翻译层。DCS 游戏语言设为英文时也不会加载 CN 字典，所以不执行回滚也不影响英文体验。

3.4 修正翻译

翻译完成后，每个 .miz 同目录下会生成 *_translateRef.json 文件（英文→中文对照表）。可以手动编辑纠正错误的翻译，然后运行合并命令：

python fix_translate.py /path/to/missions

这会将所有修正后的翻译合并到 ./cache/translated.json 词典中供参考。

4. 输出格式说明

翻译结果按 DCS 字典字段类型应用不同的格式规则：

字段类型中英混排（默认）仅中文（--only-chs）
普通文本 原文
译文		 译文
Radio 字段
（键名含 "Radio"）		 [原文][译文] 译文
Script 字段
（键名含 "Script"）		 原文[译文] [Script]译文
为什么不同字段有不同格式？ 这是 DCS 引擎的解析约定。[ ] 括号在 DCS 的字典系统中用于分隔原文和译文，Radio 和 Script 字段有特殊的显示逻辑。

5. 处理链路详解

1
提取字典 从 .miz (ZIP) 中提取 l10n/DEFAULT/dictionary，Lua 表 → JSON
2
过滤不可翻译内容 跳过 Name 字段、DictKey 引用、Lua 代码、长度 <2 的字符串
3
内容哈希 MD5 计算 → "md5_{32位hex}" 作为缓存键
4
缓存查找 本地缓存(瞬时) → 远程缓存(补充) → 未命中则 LLM 翻译
5
动态术语注入 扫描原文，从 97 条术语库中匹配相关条目，注入提示词
6
LLM 翻译 DeepSeek v4 Pro，reasoning_effort=high。180s 超时 + 3次指数退避重试。多文件通过线程池并发执行v2.3
7
解析输出 正则提取 <input_id> 标签，校验数量。空结果保存 raw 后将该文件标记为失败，不中止其余任务v2.3
8
术语后处理校正 Pass 1: keep 术语被误翻译的还原 | Pass 2: brevity 漏翻的补译
9
应用翻译 + 回写 按字段类型混排，写 _translateRef.json，JSON→Lua 写回 .miz

6. 缓存系统

6.1 缓存优先级

本地缓存 (毫秒级) ──miss──▶ 远程缓存 (秒级) ──miss──▶ LLM 翻译 (API)

本地优先的设计确保已有翻译零网络延迟返回，远程仅作为社区补充。

6.2 本地缓存文件

文件内容格式
md5_{hash}_translated.json解析后的翻译字典JSON dict
md5_{hash}_raw.txtLLM 原始响应纯文本（调试用）
config.json持久化配置JSON
trans.log运行日志（自动轮转 1MB×5）v2.3文本

6.3 远程社区缓存

翻译结果可上传至社区服务器供他人复用。同样，你也能受益于他人的翻译结果——即使没有自己的 API Key 也能使用（前提是内容已被他人翻译过）。

隐私提示：远程缓存上传的内容是翻译字典（DictKey → 中文），不含任务文件的其他信息。如介意，使用 --no-remote 完全禁用。

6.4 缓存命名迁移

旧版缓存文件以裸 MD5 哈希命名（如 a1b2c3_translated.json），无法区分哈希算法。v2.1 起使用 md5_ 前缀（如 md5_a1b2c3_translated.json）。旧格式文件在首次访问时自动重命名为新格式，无需手动迁移。

7. 军事术语处理

程序采用三层防御确保军事术语翻译正确：

层级时机机制
静态提示词 每次 LLM 调用 核心规则 + 16 对翻译示例，定义基础翻译策略
动态术语注入 LLM 调用前 扫描当前待翻译文本，从 97 条术语库中匹配，仅注入相关条目到提示词
后处理校正 LLM 调用后 自动修正：keep 术语被误翻译的还原为英文，brevity 漏翻的补译为中文

术语库位于 util/military_glossary.json，包含 6 个类别共 97 条：

类别条目数策略
mission_types（任务类型）10保留原文
roles_and_platforms（角色/平台）9保留原文
threat_systems（威胁/武器系统）11保留原文
brevity_translate（战斗用语）49必须翻译
navigation_and_ops（导航/作战）11保留原文
weapon_codes（武器码）10保留原文
扩展术语库：编辑 util/military_glossary.json 即可添加新术语，下次运行自动生效。欢迎向社区贡献新条目。

8. 配置与持久化 v2.2

程序自动在 ./cache/config.json 保存以下选项：

{
  "api_key": "sk-xxxx",
  "path": "E:/DCS/Missions, G:/Missions/F-14A",
  "only_chs": false,
  "remove_json": false,
  "use_remote_cache": true,
  "threads": 0
}
  • 命令行模式：--api-key 和 --path 的值在翻译完成后自动保存
  • 交互模式：每次确认后保存所有选项，下次按回车即可沿用
  • API Key 安全：存储在本地 cache/ 目录（已 gitignore），显示时遮罩为 ********cdef
安全提醒：API Key 以明文存储在 ./cache/config.json。请勿将此文件分享给他人或提交到 Git 仓库。该目录已在 .gitignore 中排除。

9. 构建独立 EXE

9.1 Nuitka（推荐）v2.3

Nuitka 将 Python 编译为原生机器码，性能优于 PyInstaller：

pip install nuitka

nuitka --standalone --onefile \
  --enable-plugin=upx \
  --upx-binary="upx.exe" \
  --windows-icon-from-ico=./favicon.ico \
  --lto=yes \
  --include-data-files=util/military_glossary.json=util/military_glossary.json \
  --output-filename="transyytg_con_cl v2.3.exe" transyytg_con_cl.py
重要：--include-data-files 必须包含 military_glossary.json（军事术语库），否则打包后的 exe 运行时将报错找不到该文件。

生成单个 .exe 文件，双击即可运行。exe 所在目录会自动创建 cache/ 存放配置和翻译缓存。

9.2 PyInstaller（备选）

pip install pyinstaller
pyinstaller -F transyytg_con_cl.py -i favicon.ico

如需包含自定义图标，将 .ico 文件放在项目根目录。

10. 故障排除

问题可能原因解决方案
找不到 .miz 文件 路径不正确或 .miz 不在目录根层 确认路径，.miz 文件需在指定目录的直接子级
翻译过程中报错 API Key 无效或余额不足 检查 DeepSeek 控制台
LLM 调用超时/失败 网络波动或服务端繁忙 自动重试最多 3 次（3s/6s/12s 退避），单文件失败不中止整个任务v2.3
LLM 返回无法解析 模型输出了非预期格式 查看 ./cache/*_parse_error.txt 排查原始输出
部分条目未翻译 条目被过滤（Lua代码、过短文本） 正常现象，这些条目本就不应翻译
远程服务器不可用 服务器维护或网络问题 自动回退本地+LLM，不影响使用；也可 --no-remote
翻译质量不佳 模型对特定术语处理不当 编辑 _translateRef.json 修正，运行 fix_translate.py
想恢复英文原版 — --rollback --path "..."
交互模式每次都重新输入 配置文件未生成 完成一次完整翻译流程后自动保存，下次即可使用默认值
exe 双击没反应 无法创建 cache 目录或无依赖缺失 在命令行运行 exe 查看错误输出；确保 exe 所在目录可写
打包后报错找不到术语库 Nuitka 未包含数据文件 添加 --include-data-files=util/military_glossary.json=util/military_glossary.json
